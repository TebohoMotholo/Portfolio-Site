Case study

Endpoint migration lab

A small company's Windows estate, built from scratch on one PC and moved from Active Directory, Group Policy and Configuration Manager to Microsoft Entra ID and Intune.

  • Completed Nov 2026
  • Proxmox VE
  • pfSense
  • Active Directory
  • Configuration Manager
  • Entra ID
  • Intune

Goal

Run a full SCCM to Intune migration from start to finish, the way an enterprise would: build the on-premises estate first, then move it to the cloud one workload at a time. It builds on the migration I took part in at Redial BPO, where I worked alongside the engineer who led it.

This is a home lab, not a production environment. It runs on one PC and a Microsoft 365 trial tenant. I built, broke and fixed every part of it myself.

The lab

Hover, tap or tab to a block for details.

What I built

  • Virtualisation and network: Proxmox VE with two bridges (one isolated), pfSense with NAT and WireGuard, and scheduled backups to an external drive with retention.
  • Identity: Active Directory with two domain controllers, DNS and DHCP, then Entra Connect Sync and hybrid join to Entra ID.
  • On-premises management: Group Policy, file services, and a Configuration Manager site with SQL Server.
  • Cloud management: Intune with co-management, Group Policy analytics, Settings catalog profiles and Win32 apps.
  • Intune Suite: Endpoint Privilege Management, Windows Autopatch and Remote Help.

What I migrated

  • Exported every Group Policy Object, ran them through Group Policy analytics, and rebuilt the supported settings as Intune profiles. Validated on a pilot device first.
  • Repackaged Configuration Manager apps as Intune Win32 apps. 7-Zip installs through Intune on the pilot devices.
  • Moved the pilot device to co-management, with workloads handed from Configuration Manager to Intune one at a time.
  • Collected evidence for every phase with read-only PowerShell and bash scripts, plus 34 portal screenshots. Secrets, tenant IDs and public IPs are redacted.

Problems I solved

Eleven real issues are written up with symptom, diagnosis, root cause and fix. Some of them:

  • Entra Connect failed with AADSTS700027. The certificate looked expired but was not valid yet. Every server was in the wrong time zone, so UTC was 9 hours ahead. Nothing on-premises noticed because all the servers were wrong together.
  • ConfigMgr failed every SQL check. The real cause was TCP/IP being off on SQL Server, not the settings the check named. I found it by connecting the way Setup does, using the server name.
  • Sysprep blocked on the Windows 11 template. The virtual TPM made Windows turn on BitLocker by itself. The log said so in one line.
  • A Win32 app failed on every device. The same error on a fresh device pointed at the package. One wrong install command.
  • DC02 stopped replicating. Error 1398 means the clocks differ. The time fix had only been applied to the other servers.

What is still open

I am listing these on purpose, because the lab is a practice environment and not everything reached the end.

  • Windows Autopilot: the profile and group are built, but no device has been registered yet.
  • Windows Hello with Cloud Kerberos Trust: the cloud ticket is issued and file shares open without a prompt, but a Hello PIN is not provisioned yet.
  • VLC Win32 app: the install command is fixed and waiting on a retry.
  • Next phase: Conditional Access, BitLocker, LAPS and attack surface reduction, then Azure Virtual Desktop, Windows 365 and retiring Configuration Manager.
